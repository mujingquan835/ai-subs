# AI 订阅管家开发文档

版本：0.1（开发前规格）  
日期：2026-11-15  
状态：需求与开发方案，尚未实现或验收  
暂定产品名：AI 订阅管家

## 1. 产品目标

制作一个 macOS 原生应用，集中管理国内外 AI 服务订阅。用户通过“服务图标＋名称”快捷选择项目，记录地区、订阅渠道、支付方式、费用和扣费日期；在 App 与 macOS 桌面小组件中查看下一次扣费倒计时，并在扣费前收到提醒。

典型场景：用户为 Codex / ChatGPT、Claude 等服务付费，部分使用苹果美区账号和礼品卡余额，希望提前准备余额或决定是否续订。

成功标准：能完成“选择服务 → 填写订阅 → 查看下一次扣费 → 提前收到通知 → 通过桌面组件持续查看”的完整流程。

### 1.1 已确认需求

- 优先使用适合的开源项目；没有满足需求的成品时自行开发。
- 国内外常用 AI 服务可快捷录入，显示直观的服务图标。
- 同一服务可记录不同地区、渠道、金额和周期。
- 记录开始日期、每月扣费日期，自动显示还有几天扣费。
- 支持扣费前 3 天提醒。
- 打开 App 能查看，macOS 桌面也有小组件。

### 1.2 本文建议的实施决定

以下是开发默认方案，并非用户逐项指定：macOS 14 起、SwiftUI 原生界面、WidgetKit 小组件、本地 JSON 存储、系统本地通知、离线可用。产品名、配色和 App 图标暂不固定。

金额示例“19.99 美元/月”来自用户描述，只用于说明字段，不代表核实后的官方价格。

## 3. 第一版范围

### 3.1 必须交付

1. 服务目录：按国内外分组、名称搜索、图标选择、自定义服务。
2. 订阅新增、编辑、删除；同一服务允许多条记录。
3. 月付、年付和自定义每 N 月周期；首版提供独立的“到期不续订”模式。
4. 下次扣费日期、剩余天数、原币金额和状态。
5. 默认提前 3 天提醒，可改为当天或提前 1、7 天；选择通知时间。
6. 小、中、大三种桌面组件，显示即将扣费的订阅。
7. JSON 备份导出和经确认的恢复导入。
8. 中文界面、浅色/深色模式及键盘基本操作。

### 3.2 后续版本

- iCloud 同步、菜单栏入口、人民币估算与汇率、费用趋势。
- 礼品卡余额与充值记录、余额不足预测。
- 免费试用、暂停与恢复、促销价、税费明细。
- AI 额度查询和额度重置倒计时。

第一版的地区与支付方式用于记录；不会连接银行、Apple 账户或 AI 账户核验扣费。过了预计扣费日仅代表日程进入下一周期，不代表支付成功。

## 4. 服务目录与图标

### 4.1 建议初始目录

国际服务：ChatGPT / Codex、Claude、Gemini、Cursor、GitHub Copilot、Perplexity、Grok、Midjourney、Runway、ElevenLabs。

国内服务：DeepSeek、豆包、通义千问、Kimi、智谱、文心、即梦、可灵、腾讯元宝。

此目录用于快捷选择，不表示每项都有个人订阅或固定价格。无合适套餐时允许直接填写自定义名称和费用。国内外分组指产品目录组织方式，和用户实际账单地区独立。

### 4.2 选择交互

- 添加订阅时先出现可搜索的图标卡片，采用截图中的“图标＋名称”形式。
- 点击后突出选中状态，打开或推进至订阅表单。
- 显示常用服务和全部服务；常用排序可按本地使用次数生成。
- 提供“自定义项目”，填写名称并选择本地图标。
- App 列表和组件复用同一图标，避免重复辨认。

图标打包在本地，不依赖运行时在线下载；处理品牌图标来源和使用条件。缺失时显示带颜色的首字或缩写作为明确的占位。自定义图片限制格式、尺寸和文件大小，导入时转为统一格式并随备份携带。

### 4.3 套餐与命名

服务、订阅套餐、显示名称分开。ChatGPT / Codex 默认使用同一服务入口，用户可将记录命名为“Codex 主账号”；独立订阅由用户新增另一条，避免仅因客户端不同重复记账。

预设只填入图标和名称，地区、金额、周期由用户确认。不维护未经核实的自动价格表。

## 5. 订阅字段

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| 服务 | 必填 | 目录服务或自定义项目 |
| 显示名称 | 必填 | 默认服务名，可改为“Claude 工作账号” |
| 套餐名称 | 可选 | 自由填写，不依赖在线套餐数据库 |
| 账号标签 | 可选 | 便于区分多账号，无需记录密码 |
| 账单地区 | 必填 | 中国大陆、美国、日本等；支持其他/自定义 |
| 订阅渠道 | 必填 | 官网、Apple App Store、Google Play、其他 |
| 支付方式 | 必填 | 礼品卡余额、银行卡、支付宝、微信、其他 |
| 金额 | 必填 | 大于等于 0，保留币种支持的小数精度 |
| 币种 | 必填 | 首版支持 USD、CNY、HKD、JPY、EUR、GBP |
| 开始日期 | 必填 | 用户实际开始使用或订阅日期 |
| 首次计划扣费日期 | 必填 | 明确的账单锚点，不强制等于开始日期 |
| 周期 | 必填 | 每月、每年、每 N 月、到期不续订 |
| 账单时区 | 必填 | 默认录入时系统时区，允许调整 |
| 提醒 | 必填 | 开关、提前天数、通知时间；默认 3 天、09:00 |
| 备注 | 可选 | 充值说明、取消续订提示等 |

“美国地区”不会自动推断为某个美国时区。币种与地区也不强制绑定，以实际账单为准。

录入成功前显示确认摘要：“每月 15 日，19.99 USD，下次 12 月 15 日，提前 3 天提醒”。下一次日期由示例数据实时计算，文案不得写死。

## 6. 页面与组件

### 6.1 App 首页

顶部显示“最近一次扣费”和“未来 30 天预计扣费”，汇总按币种分组，不把 USD 和 CNY 直接相加。无记录时展示添加入口，不创建看似真实的默认订阅。

主体按下次日期升序排列，展示图标、名称、地区/渠道简述、金额/周期、下次日期和“还有 N 天/今天扣费”。3 天内使用更明显的提示，但同时保留文字，避免只靠颜色。

支持名称搜索和“全部、7 天内、已结束”筛选；同日记录保持稳定排序。

### 6.2 新增与详情

新增流程：选服务 → 填账单信息 → 核对下次日期与提醒 → 保存。

详情显示全部字段，提供编辑、删除和“到期不续订”。删除需确认，并取消该条提醒与更新组件。到期不续订保留最后到期日期，日期过后进入已结束，不继续产生未来扣费。

### 6.3 macOS 小组件

| 尺寸 | 默认内容 |
| --- | --- |
| 小 | 最近一项的图标、名称、金额、剩余天数和扣费日期 |
| 中 | 最近 3 项，逐行显示图标、名称、金额和剩余天数 |
| 大 | 最近 6 项，保留完整日期；空间不足时优先保证可读性 |

所有尺寸支持“即将扣费”与“指定一项”配置。指定记录被删除时显示重新选择提示；无数据时显示添加订阅入口。点击记录通过应用内链接打开详情；点击空状态进入新增页面。

组件读取与 App 相同的账单计算逻辑，按账单时区的日期边界生成刷新时间线。WidgetKit 由系统调度，验收以日期和天数正确为重点，不承诺秒级刷新。App 保存、更改和删除时请求刷新组件。

## 7. 日期计算规范

### 7.1 日历周期

- 使用公历和记录的账单时区计算，按日历月/年推进，不能以 30 天或 365 天代替。
- 每月 31 日遇到短月时使用当月最后一天，下一个长月恢复为 31 日；必须保留原始锚点，不能从截短后的日期继续漂移。
- 年付 2 月 29 日在非闰年使用 2 月最后一天，闰年恢复为 2 月 29 日。
- 每 N 月从首次计划扣费日期按 N 月间隔推算，跨年不改变周期。
- 账单当天显示“今天扣费”，直到该账单时区当天结束后才展示下一周期。
- 开始日期允许早于首个计划日期；首次计划日期允许在过去，以便录入已有订阅。

### 7.2 剩余天数与提醒

剩余天数是账单时区下两个日历日期的差，不是剩余秒数除以 86400。提醒在账单时区的扣费日前 N 天指定时间触发；遇夏令时不存在的时间，选当天后续第一个有效时间，重复时间取第一次。

编辑日期、时区、周期或提醒设置时，取消旧计划后重新生成。新增时提醒时间已经过去，不补发所有历史通知；App 内显示当前状态。休眠或关机期间的通知交付由系统控制，不能承诺精确送达或关机提醒。

自动续期仅推进“预计扣费日程”。界面避免显示“已扣款成功”，也不虚构付款历史。

## 8. 技术方案

### 8.1 架构

- Swift + SwiftUI：App 页面与表单。
- Foundation：独立、可测试的账单计算模块。
- WidgetKit + App Intents：组件展示与配置。
- UserNotifications：本地提醒。
- Codable JSON：版本化本地存储和备份，金额使用 Decimal 的精确字符串编码。
- App Group：共享 App 与组件的记录快照与图标。

采用 JSON 是第一版的工程选择：数据量小、易导出和迁移。后续数据复杂度明显增加时再评估 SwiftData，不预先引入服务器。

### 8.2 目录建议

```text
AISubscriptions/
  README.md
  AGENTS.md
  AISubscriptions.xcodeproj/
  App/                 # 页面、通知与文件导入导出
  Shared/              # 模型、日期算法、目录、数据读取
  Widgets/             # 组件与配置 Intent
  Resources/           # 图标、服务目录、来源声明
  Tests/               # 日期、存储、迁移、提醒计划测试
  docs/                # 需求、开发、验收、发行记录
  scripts/             # 构建与检查
```

正式开发时建立独立项目目录和 Git 仓库，补齐 README、AGENTS、忽略规则及验收记录。当前文档保存在现有工作区，不将“电视”目录名作为产品名称。

### 8.3 核心数据结构

```text
Subscription
  id: UUID
  serviceID, displayName, planName, accountLabel
  region, channel, paymentMethod
  amount: Decimal, currencyCode
  startDate: LocalDate
  billingAnchor: LocalDate
  intervalMonths: Int?      // 月付 1、年付 12；单次为空
  renews: Bool
  finalDueDate: LocalDate?  // 停止续订后的最后日期
  billingTimeZoneID
  reminderEnabled, reminderDaysBefore, reminderLocalTime
  notes, createdAt, updatedAt

DatabaseEnvelope
  schemaVersion
  subscriptions
  customServices
```

LocalDate 是年/月/日值，不用 UTC 午夜代替。nextBillingDate 和 daysRemaining 由算法计算，不作为权威持久字段。

### 8.4 存储与并发

App 是唯一记录写入方；组件只读，配置独立。保存时校验完整数据并原子替换，成功落盘后才更新界面、通知与组件。保留最近一次有效备份，损坏时显示恢复选项，不自动覆盖为新空库。

App Group 标识、Bundle ID 和签名团队在实施时确定。开发首日必须先验证“宿主 App＋组件＋共享读取”可签名、安装和运行；不能把签名、组件注册问题留到最后。若本机签名条件不足，明确报告组件阻塞原因，不能把仅 App 编译成功当作完整交付。

## 9. 通知、导入和异常

- 在用户首次保存开启提醒的订阅时请求通知权限；拒绝时仍允许保存，并显示系统设置入口与提醒未生效状态。
- 建立统一通知协调器，仅管理本 App 的请求。按订阅、扣费日期生成稳定 ID，防止编辑、重启和恢复导入后重复。
- 在系统待处理通知容量内安排最近的账期；App 启动和数据变更时补充计划。优先验证按月/年重复通知能否覆盖 29—31 日规则；不能准确表达的情况使用有限窗口的单次通知，并展示“已安排至某日期”。
- 长期不开 App 时通知覆盖范围是第一版必须验证和披露的限制，不承诺无限期自动补充计划。
- 导出带 schemaVersion 的 JSON 与必要自定义图标，不包含账号密码或访问令牌。
- 导入前校验版本、字段、金额、周期、时区、UUID 重复、文件大小和图片合法性；给出预览与覆盖确认，先备份旧数据。
- 首版导入采用整库替换，不做隐式合并。导入失败保留原库，不部分写入。
- 暂无网络时录入、展示和通知计划仍可使用。

## 10. 开发顺序

| 阶段 | 产出 | 通过条件 |
| --- | --- | --- |
| 0. 可行性核验 | 开源复用结论、原生 App 与组件最小工程 | 本机能签名运行，组件能读共享样例 |

## 12. 维护约定

服务目录和图标资源独立维护；任何预设价格功能必须附来源、核验日期并允许修改。数据结构修改必须带版本与迁移测试；发布前保留备份恢复、月底账期和通知计划回归检查。每次发行记录版本、变更、验证环境和已知限制。

首版优先保障账期正确、数据可靠、提醒状态透明和组件可读，后续再扩展账户同步、汇率和 AI 额度。
